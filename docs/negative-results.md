# Negative results ledger

Purpose: the project's record of what did NOT work or did NOT move, kept because a theory-checker's negative space is evidence. Author's instruction (2026-11-09): keep track of failures, rejections and null results, because that is useful data too.

Types:

- `refuted`: a preregistered claim or prediction that failed (e.g. C2b).
- `weakened`: a claim that survived only in a narrower form.
- `null`: a preregistered "no change" that came back no change (calibration hit; these count, but are listed as a group per batch, not per row: 3a, 3b, 3c each 0 of 192).
- `untested`: a claim that could not be tested (vacuous property, missing text, no API key).
- `refused`: a council seat declined to approve an edit (e.g. the 3b faithfulness seat refused mwpa R12 and footbinding R10 promotion).
- `declined`: the author rejected or shelved a proposal or experiment (e.g. 3d exp 1 exit_ground not landed; kibbutz `peers` overruled; sex left unencoded in SSI R4).
- `artifact`: a surprise that resolved to an encoding artifact rather than a finding (S1-S9 in docs/surprises.md, one row each).
- `gate_fail`: an honest gate failure (layer 2 ABM gate (a), (b), 2026-11-04).
- `abandoned`: built but not pursued (layer 2 imagination module not built; MWPA ordering backtest parked).

Rows are append-only, in date order; ids N1, N2, ...
